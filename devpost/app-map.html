  1. src/components/ForecastCards.tsx — search forecast-target and onSubmit. A personal target is saved locally and is separate from the room target.
  2. src/lib/forecast.ts — estimateForecast samples historical changes; forecastWindows defines the three date ranges.

Other main pieces

  • Rates: src/lib/rates.ts, server/twelveData.ts and server/twelveDataHistory.ts. Provider keys stay on the server.
  • Shared room: src/components/SignalRoom.tsx and src/lib/rooms.ts. Firebase stores the room; listeners update connected members.
  • Votes: src/components/Roundtable.tsx, src/lib/roundtable.ts, database.rules.json. The connected room master resolves voting. Finished rounds disappear from view.
  • Headlines: server/news.ts fetches fixed publisher feeds. src/lib/news.ts limits dates/counts and saves a small local cache. src/components/NewsBanner.tsx renders three sections.

A practice to reuse

The forecast originally stopped when the news feed failed, although rate history was still available. Its news freshness check in ForecastCards.tsx was changed to use a clearly labelled history-only result. Keep optional inputs from disabling a feature that can still produce an honest, useful result. State which inputs were used and preserve source timestamps.

Recorded evidence: checklist revisions; five-year backtest. Successful computation does not establish reliable real-world prediction.

Run and share

Install dependencies with npm install. Configure your ignored .env.local from .env.example, then run npm run dev and open http://127.0.0.1:5173. See README for Firebase and provider setup.

Public hosting needs production rate/news API routes. Email delivery is prepared but inactive. The current app is a proof of concept; the forecasts and publisher availability have limits.
